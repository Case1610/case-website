## 2026-09-10 に起きたこと

1. リポジトリを `ShowCase` → `case-website` にリネーム（サイト名は `ShowCase` のまま）
2. Vercel → Cloudflare Workers へ移行。GitHub Actions で自動デプロイを構成
3. **1年以上ビルドが壊れていたのを修復**。`profile.json` が `.gitignore` 対象なのに

   ブラウザ側の変換は表示フィルタでしかなく、実データ全体がバンドルに載っていた。

### 実データの露出は発生していない（確認済み）

3 の「ビルドが壊れていた」ことが、結果的に 4 の露出を防いでいた。根拠:

- `PROFILE_JSON_B64` は未設定で、ビルドは常にサンプルデータで走っていた
- デプロイ済みバンドルのハッシュが、サンプルデータでのローカルビルドと完全一致
- `profile.json` の import が入る前の `35d402f` が、Vercel で最後に成功したデプロイ

つまり実データ入りのバンドルは生成すらされていないため、キャッシュに残る余地もない。

## 未決の判断

**いずれも持ち主（サイトの所有者）が決めること。** セッション側で勝手に決めない。

### 1. 強み診断（CliftonStrengths）をサイトに出すか

- 全34資質のランキング（`all_ranking`）は「出さない」と決定済み（2026-09-10）。
  型からも外し、混ざった場合に備えて変換でも落としている
- **一方 `top_5` は今も About ページに表示される作りのまま**
- 正本側のメモに「経歴書には使わない自己分析用の記録と位置づけているのに、
  サイトには出す作りになっている。惰性で埋めていないか確認したい」という
  問いが立てられている。**この一段手前の判断が未決**

### 2. 表示されないまま配信されるフィールド

型にはあるが、どのコンポーネントも表示しておらず、変換対象にもなっていないもの。
値が入れば「画面に出ないのに配信される」状態になる。

| フィールド | 平たく言うと | 現状 |
|---|---|---|
| `biography['short-values']` | 日本語のキャッチフレーズ欄 | 正本側でも未記入。**今は空なので実害なし** |
| `certifications[].description.title` | 資格の正式名称欄 | 正本側で「要確認」のまま。**今は空** |

どちらも**埋める前に**「表示するのか、供給しないのか」を決める必要がある。

### 3. `nationality` の食い違い

`About.tsx` が `basicInfo.nationality` を表示しようとしているが、
`showNationality: false` により変換で削除される。結果、画面には区切り文字だけが残る。

表示するなら設定を、しないなら表示側を直す必要がある。
これは修正前からの挙動で、今回の変更で悪化はしていない。

### 4. 実データを入れるときの前提

`PROFILE_JSON_B64` を設定する前に、正本側で `*Display` 系の値を全て埋めておくこと。
書き忘れがあると**実名にフォールバックせずビルドが停止する**（安全側だが、デプロイは失敗する）。
